3. LÓGICA DE CÁLCULO DE PRECIOS
--------------------------------
Código exacto de calculateItemPrice (NuevoPedidoModal.tsx:177):

const calculateItemPrice = (materialCode, w, h, c, services) => {
    const mat = getMateriales().find(m => m.codigo === materialCode);
    if (!mat || h <= 0) return 0;
    let currentUnitPrice = mat.precioM2 || 0;

    // Selector de Escala por Ancho
    if (mat.preciosPorAncho && mat.preciosPorAncho.length > 0) {
        const tier = mat.preciosPorAncho.find(t => w <= t.maxAncho);
        if (tier) { currentUnitPrice = tier.precio; } 
        else { currentUnitPrice = mat.preciosPorAncho[mat.preciosPorAncho.length - 1].precio; }
    }

    // Cálculo Base
    let basePrice = (mat.tipoCobro === 'ml') 
        ? Math.round(h * c * currentUnitPrice) 
        : (w > 0 ? Math.round(w * h * c * currentUnitPrice) : 0);

    // Aplicación de Servicios
    let servicesTotal = 0;
    if (services) {
        Object.entries(services).forEach(([sId, active]) => {
            if (active) {
                const s = availableServices.find(serv => String(serv.id) === sId);
                if (s) servicesTotal += (s.precioBase || 0) * c;
            }
        });
    }
    return basePrice + servicesTotal;
}

VALIDACIONES EXISTENTES: h > 0, material existente.
CASOS LÍMITE NO CONTEMPLADOS: No hay redondeo por desperdicio (si usas 0.10m de un rollo de 1.60m, solo cobras 0.10m). No hay recargos por urgencia automáticos.

4. LÓGICA DE STOCK
-------------------
- Descuento de Stock: NO ES AUTOMÁTICO. No hay trigger que descuente stock al imprimir o entregar.
- Gestión: El usuario debe ir a la pestaña "Stock" y usar el botón "Ajustar" (Stock.tsx:38).
- Tipos de Ajuste: "add" (Ingreso), "subtract" (Egreso), "set" (Fijar).
- Sincronización: Está totalmente desacoplado del precio. Un cambio en Stock no afecta el precio unitario del material.
- Inconsistencia Actual: Posibilidad de vender sin stock. No hay bloqueo de ordenes si el stockActual < cantidad solicitada.

5. FLUJO DE CREACIÓN DE ORDEN
------------------------------
1. Subida de Archivo: NuevoPedidoModal.tsx maneja el upload vía uploadFile (db.ts).
2. Metadata: Se extrae DPI, dimensiones y modo color del archivo (pdf-lib / custom parsers).
3. Selección de Material: El usuario elige el código. Esto gatilla calculateItemPrice.
4. Confirmación: onSubmit valida campos requeridos.
5. Persistencia: El server (index.js) recibe el POST, asigna ID incremental, genera el código de OT, renombra los archivos físicamente en /uploads usando la fórmula ID_CLIENTE_MAT... y guarda en ordenes.json.

6. LIMITACIONES TÉCNICAS ACTUALES
----------------------------------
- Frontend-Dependencia: El cálculo de precio ocurre en el cliente. Un usuario con conocimientos técnicos podría inyectar un subtotal arbitrario en el POST antes de que llegue al servidor.
- Seguridad: No hay validación de precios en el backend (server/index.js). El servidor acepta el subtotal que envía el frontend sin recalcularlo.
- Integridad: Si cambia un precioM2 en el maestro de materiales, las órdenes viejas mantienen su precio (lo cual es correcto), pero no hay histórico de cuándo cambió el precio.
- Edición Manual: Editar el JSON manualmente es seguro mientras se respete el formato, pero si se corrompe el JSON, el sistema falla (getOrders devuelve [] en caso de error de parseo).
